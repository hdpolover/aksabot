#### Hardware Findings
- **Touch axis**: needs `x_min=239, x_max=0, y_min=319, y_max=0` (inverted from default)
- **ES8311 clock**: manufacturer uses `pre_div=3, pre_multi=1 (2x)` for 16kHz with 6.144MHz MCLK. We were missing `pre_multi`, fixed.
- **I2S port**: manufacturer uses `I2S_NUM_1`, not `I2S_NUM_0`
- **L/R channels identical**: ES8311 outputs same data on both stereo channels
- **DC offset**: raw mic samples sit at ~+1400 DC offset (not centered at 0). HPF filter added but didn't fully solve playback noise.
- **WiFi + BLE coexistence**: crashes if both run simultaneously. Fix: sequential — BLE first (provisioning), stop BLE, then start WiFi.
- **Mic gain tuning**: 18dB too quiet, 36-42dB causes feedback noise. 24-30dB range seems best.

#### BLE Provisioning (working!)
- Firmware advertises as "Aksabot" with GATT service 0xFFE0
- Flutter app scans, connects, writes SSID + password
- Firmware notifies status=1 (connecting), tries WiFi
- On success: notifies status=2, stops BLE → app shows "Done"
- On failure: notifies status=3 → app shows error, BLE stays alive for retry
- App updated to handle BLE disconnect-during-connecting as success

### Audio Issue — UNSOLVED

**Symptom**: Playback has constant beeping tone + voice sounds robotic/unclear. Both RAW and Opus modes affected.

**What we know**:
- Mic reads valid data (RMS 400-1700 when speaking, 3-10 idle)
- Raw stereo samples: L and R are identical, values around +1400 DC
- DC offset is large (~1400) and fluctuates (-2000 to +2000)
- HPF (IIR, alpha=0.975) doesn't fully solve it
- I2S DMA buffer clearing between record/playback doesn't help
- Using I2S_NUM_1 (manufacturer's port) doesn't help

**Likely causes to investigate next**:
1. **ES8311 DAC initialization** — we init ADC registers for mic but may be missing DAC-specific registers. The manufacturer's `es8311_codec_init()` calls `es8311_init()` which sets system registers (0x0B-0x11), but our manual register writes may be incomplete or in wrong order.
2. **MCLK configuration** — the `fixed_mclk` setting in legacy I2S driver may not produce the exact 6.144MHz the ES8311 expects. The manufacturer uses the new I2S driver which has `mclk_multiple` support.
3. **Best approach**: port the manufacturer's exact `es8311.cpp` + `es8311.h` driver and use it directly, instead of manual register writes. The challenge is it requires ESP-IDF 5.x I2S API (`driver/i2s_std.h`). Options:
   - Upgrade to `pioarduino` platform (ESP-IDF 5.x + Arduino 3.x)
   - Or adapt the manufacturer's register sequence to work with legacy I2S
