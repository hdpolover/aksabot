### What was done this session

#### 1. TTS greeting on device connect
- Backend `sendConnectionGreeting()` generates text via `ProactiveService.checkGreeting()`, synthesizes TTS, sends as `response:start` → paced Opus frames → `response:end`
- Daily dedup preserved across disconnects (don't clear `lastGreetingDate` on disconnect)
- Greeting text split into sentences for per-sentence TTS (matching conversation pipeline)

#### 2. Audio playback architecture
- **Playback queue**: WS callback decodes Opus and enqueues PCM frames (non-blocking). Audio task on Core 0 dequeues and plays with `portMAX_DELAY`.
- **Jitter buffer**: 200ms of audio buffered before playback starts. Absorbs network jitter.
- **Frame pacing**: Backend sends 5 frames then pauses 75ms. Prevents ESP32 TLS buffer overflow.
- **Opus encoding**: Backend set to 64kbps AUDIO mode (was unset ~6kbps). Near-transparent quality.
- **Static stereo buffer**: `writeSpeaker()` uses static buffer instead of malloc/free per frame.
- **Speaker volume**: ES8311 set to 70% to prevent clipping with TTS audio.

#### 3. Opus framing fix
- Backend Opus codec uses 2-byte BE length prefix per frame: `[len16][frame][len16][frame]...`
- Added `sendFramedOpusToDevice()` that parses this format and sends each frame as individual WS binary message
- Also fixed conversation pipeline (`runPipeline`) to use same framing

#### 4. SSL/WSS support
- ArduinoWebsockets library patched: `esp32_tcp.hpp` added `setInsecure()` method, `websockets_client.cpp` added `client->setInsecure()` fallback when no CA cert (matching ESP8266 behavior)
- Task stack sizes reduced: display 8K→6K, WS 12K→8K (audio stays at 24K for Opus)
- Playback queue reduced: 50→40 frames
- Free heap ~138KB — enough for SSL handshake

#### 5. Server-side heartbeat
- Backend pings all devices every 10s, terminates after 20s silence
- `lastSeenAt` refreshed in DB every 2 minutes (for REST API online status)
- Firmware pong timeout disabled (Traefik intercepts WS pings)

#### 6. Display improvements
- Pre-allocated PSRAM sprite buffer before WiFi init (prevents allocation failure)
- `invertDisplay(true)` for correct colors on this ILI9341V panel
- All palette backgrounds set to `rgb(0,0,0)` (pure black)
- Boot screens changed from cyan to white accent
- Reminder screen uses sprite (no flicker), word-wrapped text at size 2
- Confused face: animated floating "?" with bobbing/tilting, no glow container
- Speaking mouth: 36-52px wide, 3x amplitude boost, visible movement
- Status icons replace text labels (mic for listening, speaker for speaking)
- Eye sizes increased to r=42 for all expressions

### Key decisions

- **Opus framing**: Backend uses length-prefixed frames, firmware expects raw frames per WS message. Bridge in gateway via `sendFramedOpusToDevice()`.
- **SSL memory**: ESP32-S3 needs ~40KB contiguous heap for TLS. Reduced task stacks and queue to fit.
- **Pong timeout disabled**: Traefik reverse proxy intercepts WS pings — firmware-side dead connection detection doesn't work. Backend heartbeat handles it instead.
- **Jitter buffer**: 200ms (10 frames) accumulated before playback starts. Trades latency for smooth audio.
- **Display inversion**: This ILI9341V panel needs `invertDisplay(true)` — colors were inverted without it.
- **PSRAM sprite pre-alloc**: Must happen before WiFi init grabs memory. Otherwise sprite allocation fails → direct draw → flicker.
