### Bugs found and fixed during E2E testing
- `@discordjs/opus` segfaults on macOS → replaced with `opusscript` (pure JS)
- Opus codec failed on full TTS buffer → frame-by-frame encoding with 2-byte length prefix
- Google STT streaming expected raw PCM, not `{audioContent}` wrapper
- Gemini `systemInstruction` must be Content object, not plain string
- Gateway race condition: message handler registered after async setup → moved before
- Response pool eager refill on every connect drained API budget → made lazy (fills on first use)

## Decisions

- **`opusscript` over `@discordjs/opus`** — Native bindings segfault after 1-2 encodes on macOS. opusscript is pure JS (WASM), slightly slower but stable. Fine for backend; ESP32 uses native libopus anyway.
- **Lazy response pool** — Pool entries generate on first reminder fire (batch of 5), not on device connect. Prevents 10+ Gemini calls per reconnect. Background refill every 6h via cron.
- **Opus frame format** — TTS audio encoded as `[len16][opus_frame][len16][opus_frame]...` with 2-byte big-endian length prefix per frame. ESP32 reads length, extracts frame, decodes, plays.
- **500ms post-connect delay in simulator** — NestJS WsAdapter needs time for async setup before message handler is ready. Real ESP32 won't have this issue (hardware init takes seconds).
- **Uncommon ports** — NestJS: 4280, PostgreSQL: 5489, Redis: 6312 (avoid conflicts with other dev projects)
