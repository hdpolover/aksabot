# Session: Face Animation V2 — Rounded Rectangle Style

**Status:** In progress — v2 style implemented for IDLE, HAPPY, SPEAKING. All other expressions still use original circle/ellipse style.

---

## Decisions

### Why v2?
The original procedural face used `fillSmoothCircle` (radius 42) eyes with an iris + pupil. The reference image (`sprites/samples/idle_0.png`) showed a flat rounded-rectangle eye style — more geometric, more "screen character" than organic cartoon. Decision: keep the procedural animation engine (no sprites — full audio reactivity preserved) but change the drawing primitives to match the new visual language.

### Why not sprites?
Sprites were considered and rejected. The procedural system has continuous audio-reactive eye scale, amplitude-driven mouth, smooth interpolation between states, and 11 idle micro-animations. Sprites can only step between discrete frames — all of that dynamism would be lost. See conversation history for full trade-off discussion.

### Shape language
- **Eyes:** `fillRoundRect` (rounded rectangle) — flat fill, no pupil, no iris ring
- **Mouth (talking):** `fillRoundRect` slot that grows in height — matches eye language
- **Mouth (closed/resting):** bezier curve line — neutral, works with both styles
- **Corner radius:** 8px everywhere — consistent across eyes and mouth

## Modified files

### `firmware/src/display.cpp`

All v2 changes are gated behind `static bool g_idleStyleV2 = true;` at line 64. **Set to `false` to fully revert to original style instantly.**

#### New function: `drawEyeV2()` (around line 225)
Replaces `drawEyeOpen()` for v2 expressions. Key parameters:
- `scaleY` — blink scale (same contract as `drawEyeOpen`)
- `driftX/Y` — shifts entire rect (no pupil; whole eye moves instead)
- `squintBot` — 0=flat bottom, 1=bottom lid fully risen. Top stays fixed, only bottom half closes.
- `eyeW/eyeH` — per-expression dimensions (defaults: 68×38)

#### V2 eye behaviour per expression

| Expression | Eye size | Squint | Drift |
|---|---|---|---|
| IDLE | 68×38 | none (0.0) | full ±10/±5px |
| HAPPY | 72×38 | 0.15 resting + 0.65×mouthAmp, capped 0.75 | none (eyes locked forward) |
| SPEAKING | 68×38 | 0–0.30 driven by mouthAmp | 25% damped |

#### V2 mouth behaviour (in `drawMouth()`)

| Expression | Closed | Talking |
|---|---|---|
| IDLE | bezier smile (breathing offset) | 60px wide rect slot, 6→46px tall |
| SPEAKING | — | 68px wide rect slot, 8→54px tall |
| HAPPY | bezier smile (kept) | 70px wide rect slot, 8→50px tall, +4px lower |

Inner shadow: smaller `fillRoundRect` in `blendRGB565(pal.accent, pal.bg, 20)` drawn on top when tall enough — gives depth without breaking flat language.

## Next steps (priority order)

1. **Flash and test on hardware** — verify the rect eyes look correct on the actual ILI9341V display. The simulator renders differently to hardware (no anti-aliasing on real SPI pushImage).

2. **Tune eye dimensions if needed** — tweak `eyeW=68, eyeH=38` defaults in `drawEyeV2()` signature. Happy eyes are `72×38`, speaking `68×38`. These were chosen based on the 240×320 display and EYE_SPACE=48.

3. **Extend v2 to remaining expressions** — suggested approach per expression:
   - **LISTENING:** wider eyes (74×38), no squint, no drift (alert/focused). Mouth keep small oval dot — it reads as "O" shape which is fine.
   - **THINKING:** narrow eyes (60×30, squintBot=0.2 constant — relaxed squint). Mouth already uses side-to-side shifting oval which works, or replace with small rect that shifts.
   - **FOCUSED:** squinted rect (60×34, squintBot=0.25 constant). Tight rect mouth matching eye width.
   - **CALM:** soft rect (64×36, squintBot=0.1). Gentle opening rect mouth.
   - **SAD:** drooped look — harder with pure rect. Options: (a) use `drawEyeV2` with squintBot on TOP instead of bottom (requires new `squintTop` param), (b) keep circle eyes for SAD only.
   - **CONFUSED:** asymmetric — different squintBot per eye (left=0, right=0.2 or vice versa). Pass different values to left/right `drawEyeV2` calls.
   - **ENCOURAGING:** wide (76×40), squintBot=0.1, eyebrows above rect.
   - **SLEEPING / OFFLINE:** these have special rendering paths, handle separately.

4. **Eyebrow compatibility** — `drawBrow()` currently positions relative to `eye.r` (circle radius). For v2 expressions with brows (ENCOURAGING, HAPPY, SHRUG), the brow Y position uses `eyeY - leftEye.r - 6`. Since v2 eyes don't use `EyeShape.r`, brows won't draw for HAPPY/ENCOURAGING in v2 mode. Fix: after `drawEyeV2()` calls, manually draw brows at `eyeY - eyeH/2 - 8` for expressions that need them.

5. **Consider extracting v2 constants** — `eyeW`, `eyeH`, squint values, and mouth slot widths could go in a `FaceStyleV2` struct at the top of `display.cpp` for easier per-expression tuning without hunting through the render code.
