**Session: LovyanGFX + touch + WS stability — display, touch, and WebSocket all working**

## Status

Major firmware rework: TFT_eSPI replaced with LovyanGFX (display + touch), touch input reliable, WebSocket stable, face expressions visually distinct per state.

### What was done

1. **TFT_eSPI → LovyanGFX** — display driver swap with runtime config
2. **Touch driver rewrite** — replaced manual FT6336G I2C with LovyanGFX `Touch_FT5x06`
3. **Face expressions made visually distinct** — each expression now has unique eye shapes, mouth, and visual elements
4. **Touch visual feedback** — tap/hold/wake produce visible face reactions
5. **WebSocket stability** — mutex for thread safety, keepalive pings, connect guard
6. **Power manager underflow fix** — uint32 wraparound guard

### Key fixes

**Display scrolling** — SPI bus config needed `spi_3wire`, `use_lock`, `dma_channel = SPI_DMA_CH_AUTO`, `bus_shared = false`. SPI at 40MHz.

**Touch phantom events** — FT6336G I2C returned spurious touches. Fixed: INT pin gating (`digitalRead(TOUCH_INT) == LOW`), 3-sample debounce, 80ms minimum between transitions, 500ms wake cooldown.

**I2C bus conflict** — Touch and ES8311 share GPIO 15/16. LovyanGFX Touch_FT5x06 on I2C port 0 (shared with ES8311). Setting port 1 crashed ES8311 init.

**Immediate sleep after wake** — `power_manager::recordInteraction()` calls `millis()` internally, newer than the `nowMs` snapshot in `tick()`. Guard: `if (nowMs < lastInteractionMs) return;`.

**WS crash on audio recording** — audio capture task (Core 0) called `sendBinary()` while WS poll task (Core 1) ran `poll()`. ArduinoWebsockets is NOT thread-safe. Fixed with FreeRTOS mutex around all client operations. `sendBinary` uses 10ms timeout (drops frame if busy).

**WS reconnect loop** — `connect()` was called overlapping with existing connection. Added `connecting` flag guard. Keepalive pings every 20s, pong timeout 30s (only after first ping sent). WS task stack increased 8KB → 12KB.
