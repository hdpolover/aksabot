## What was done this session

### Context

The previous sessions built 18 firmware modules and a full Flutter app, but the provisioning flows had hard dependencies on the backend being available. This session replaced that assumption with a self-contained pairing path: **the device and app can connect to each other and to the internet without a backend being reachable first**.

### Step 1 — Local device persistence (Flutter)

**Goal**: after provisioning, the home screen shows the device even when the backend is offline.

**Flutter — new files:**
- `app/lib/core/local/local_device.dart` — `LocalDevice` model (id, name, ssid, pairedAt, localIp?) with `copyWith`, `toJson`, `fromJson`
- `app/lib/core/local/local_device_store.dart` — SharedPreferences-backed store; `getAll()`, `save()`, `remove()`, `create()`, `clear()`

**Flutter — modified files:**
- `app/lib/features/devices/presentation/pages/ble_provisioning_page.dart` — stripped backend calls; 3-step flow (scan → WiFi creds → done); saves `LocalDevice` when ESP32 reports `wifiConnected`
- `app/lib/features/devices/presentation/pages/add_device_page.dart` — SoftAP flow reduced to 3 steps; saves `LocalDevice` after HTTP POST `/provision` succeeds; removed `createDevice()` backend call
- `app/lib/features/home/presentation/pages/home_page.dart` — home page loads local devices alongside backend devices; shows `_LocalDeviceDashboard` (single) or `_LocalDeviceList` (multiple) when backend unavailable; orange "not synced" dot; `_CloudSyncBanner` explains AI features need backend

### Step 2 — Firmware SoftAP provisioning mode

**Goal**: ESP32 creates its own Wi-Fi hotspot during first-time setup so users can provision without BLE.

**Firmware — modified files:**
- `firmware/include/wifi_manager.h` — added `startAP()`, `stopAP()`, `tickAP()`, `isAPProvisioned()`
- `firmware/src/wifi_manager.cpp` — `WiFi.mode(WIFI_AP_STA)` + `WebServer(80)`; `POST /provision` accepts `{ssid, password}` JSON, writes to NVS; `GET /status` returns `{provisioned, wifiConnected}`; `tickAP()` calls `handleClient()`
- `firmware/include/boot_screen.h` — added `showFirstBoot()`, `showSetupComplete(ssid)`, `showProvisioningPrompt(apName)`, `tickProvisioningAnimation(nowMs)`
- `firmware/src/boot_screen.cpp` — `showFirstBoot()`: robot with arms icon + introduction text; `showSetupComplete()`: circle checkmark + SSID in cyan; `tickProvisioningAnimation()`: 3 cycling dots every 500ms
- `firmware/include/nvs_store.h` / `firmware/src/nvs_store.cpp` — added `isFirstBoot()`, `markSetupComplete()`; uses `setup_done` NVS key
- `firmware/src/face.cpp` — `OFFLINE` expression added to `shouldBlink()` whitelist so face always animates
- `firmware/src/main.cpp`:
  - Step 5: `nvs_store::isFirstBoot()` → shows `showFirstBoot()` intro screen
  - Step 6: dual provisioning gate — generates AP name `Aksabot-{MAC}`, starts both SoftAP HTTP server and BLE simultaneously, polls `isProvisioned()` + `isAPProvisioned()` every 100ms while calling `tickProvisioningAnimation()` and `tickAP()` to keep screen alive
  - Step 7: `markSetupComplete()` + `showSetupComplete()` on first successful WiFi connection
  - Step 11: uses `wifiConnected` (not `wsConnected`) to set IDLE state — device shows face without needing backend

### Step 3 — mDNS local device discovery

**Goal**: Flutter app finds the ESP32 by hostname (`aksabot.local`) without knowing the IP address in advance.

**Firmware — new files:**
- `firmware/include/device_server.h` — HTTP server API: `start()`, `tick()`, `stop()`, `consumeNewToken()`
- `firmware/src/device_server.cpp` — `WebServer(80)`; `GET /` returns `"Aksabot"`; `GET /status` returns `{name, version, mac, ip}` JSON; `POST /token` (added in Step 4); `consumeNewToken()` clears and returns `tokenJustReceived` flag

**Firmware — modified files:**
- `firmware/src/main.cpp` — `#include <ESPmDNS.h>`; after WiFi connects: `MDNS.begin("aksabot")` + `MDNS.addService("aksabot", "tcp", 80)` + `device_server::start()`; `device_server::tick()` in `loop()`

**Flutter — new files:**
- `app/lib/core/local/mdns_discovery_service.dart` — `MdnsDiscoveryService`; queries `_aksabot._tcp` PTR → SRV → A record chain via `multicast_dns`; returns `DiscoveredDevice(ip, port, hostName)` or null; fails gracefully when not on WiFi

**Flutter — modified files:**
- `app/pubspec.yaml` — added `multicast_dns: ^0.3.2`
- `app/android/app/src/main/AndroidManifest.xml` — added `CHANGE_WIFI_MULTICAST_STATE`, `ACCESS_WIFI_STATE`, `INTERNET`
- `app/ios/Runner/Info.plist` — added `NSLocalNetworkUsageDescription`, `NSBonjourServices: [_aksabot._tcp]`
- `app/lib/features/home/presentation/pages/home_page.dart` — `_LocalDeviceDashboard` becomes stateful; adds "Find device on network" button (`_DiscoverButton`) with idle/searching/found/notFound states; on success saves `localIp` to `LocalDeviceStore`; shows green dot + IP + `aksabot.local` when found

### Step 4 — Backend token delivery + WebSocket connection

**Goal**: user registers the already-provisioned device with the backend AI service by pushing a token over HTTP, then the ESP32 connects WebSocket automatically.

**Firmware — modified files:**
- `firmware/src/device_server.cpp` — `POST /token` handler: parses `{token, backendUrl?}` JSON, writes token to NVS via `nvs_store::setDeviceToken()`, sets `tokenJustReceived = true`; `consumeNewToken()` returns true once after token arrives
- `firmware/include/ws_client.h` — added `reconnectWithToken()` declaration
- `firmware/src/ws_client.cpp` — `reconnectWithToken()`: closes existing connection, re-reads NVS for URL + token, calls `client.addHeader("Authorization", "DeviceToken ...")` with new value, resets backoff, calls `doConnect()`
- `firmware/src/main.cpp`:
  - Setup step 8: `ws_client::connect()` now guarded by `nvs_store::hasDeviceToken()` — devices without a token skip WS connection silently instead of spamming the backend with auth failures
  - `loop()`: `device_server::consumeNewToken()` → if true, calls `ws_client::reconnectWithToken()` + `ble_manager::notifyAuthStatus(1)` + `updateStatusBar()`

**Flutter — new files:**
- `app/lib/features/devices/presentation/pages/cloud_register_page.dart` — `CloudRegisterPage(device: LocalDevice)`; phase machine: idle → registering → sendingToken → done (or error with retry); calls `DevicesRepository.createDevice(name: device.name)`, POSTs `{token}` to `http://{localIp}/token`, removes `LocalDevice` from store; returns `true` on success so caller reloads backend devices

**Flutter — modified files:**
- `app/lib/features/home/presentation/pages/home_page.dart`:
  - `_LocalDeviceDashboard` gets `onRegistered` callback + `_connectToBackend()` method that pushes `CloudRegisterPage` and calls `onRegistered` on success
  - `_CloudSyncBanner` gets optional `onConnect` callback — when set shows "Connect" action button (primary container color); when null shows plain "not synced" message (secondary container)
  - Dashboard passes `onConnect: device.localIp != null ? _connectToBackend : null` — connect only possible after mDNS discovery

## Complete user journey (as implemented)

```
Power on ESP32
  └─ Splash screen + hardware check
  └─ First boot? → "Hello! I'm Aksabot" intro screen
  └─ No WiFi credentials → Provisioning mode
       ├─ BLE: Flutter app scans → connects → writes SSID+password
       └─ SoftAP: connect to "Aksabot-XXXX" hotspot → POST /provision

ESP32 connects to WiFi
  └─ MDNS.begin("aksabot") → advertises aksabot.local + _aksabot._tcp
  └─ device_server starts on port 80
  └─ showSetupComplete() (first boot) or showConnected() (returning)
  └─ showReady() → face UI takes over

Flutter app — home screen
  └─ LocalDevice card shown (orange dot, "not synced")
  └─ "Find device on network" button → MdnsDiscoveryService queries _aksabot._tcp
       └─ Found → saves IP → green dot + "aksabot.local" shown
  └─ "Connect" button in cloud banner → CloudRegisterPage
       └─ DevicesRepository.createDevice() → gets deviceToken
       └─ POST http://{localIp}/token → ESP32 saves token to NVS
       └─ LocalDevice removed from store
       └─ Home reloads → shows backend device (green "Online" dot)

ESP32 — loop()
  └─ device_server::consumeNewToken() → true
  └─ ws_client::reconnectWithToken() → reads NVS, updates header, connects
  └─ WebSocket to backend live → AI features enabled
```
